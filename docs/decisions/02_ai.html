Decision 2: How the AI Features Work (assistant, insights, document checker)

The features the AI powers

  1. AI Assistant (top-right button in your Figma): Ask "Which supplier has ISO expiring < 90 days?" or "Total orders by grade" — the assistant queries your data and answers.
  2. AI Business Insights (the live panel in the dashboard): A nightly or on-demand job that reads your data and writes natural-language insights.
  3. Document Checker / Diffchecker (Figma pages 10/11): Upload a sales invoice or supplier invoice; AI extracts fields and reports match/mismatch/missing.

Two frameworks work together

We use two TypeScript libraries, each doing its own job:

A) Vercel AI SDK (the "chat brain")

This is how the assistant streams answers and calls your data tools.

  • useChat hook in React gives streaming answers (like ChatGPT streaming text).
  • stopWhen and prepareStep let the model decide when to keep going and which "tool" (function) to call next (the Cerebras planner pattern).

Example of the planner → tool-calling flow:

User: "Summarize JK Tyre's top grade this year"

  1. Assistant's planner (small LLM pass) chooses tools: search_records, get_monthly_stats.
  2. executor runs them in parallel on the tenant's data.
  3. synthesis LLM merges results into the final answer.
  4. Vercel AI SDK streams the answer token by token to your React panel.

B) LlamaIndex.TS (the "retrieval brain")

Handles the RAG pipeline when we need document/knowledge search:

  • Reads uploaded documents, chunks them, embeds them (into pgvector in your Postgres).
  • Exposes "tools" like search_docs, search_records to the Cerebras-style assistant.

Why two frameworks? Vercel AI SDK is great at chat/agent; LlamaIndex.TS is great at document indexing. They complement each other and both work with the same API.

Model providers — never tied to one vendor

You asked to be able to use: OpenRouter, NVIDIA NIM, Cloudflare Workers, Ollama.

We route to these providers through one layer:

Task Default provider Client can config
Embeddings NVIDIA NIM (or OpenRouter) per-tenant settings
Assistant planner+answer OpenRouter which model (e.g., cheap vs fast)
Document extraction OpenRouter (vision/extraction-capable model) switchable
Local dev Ollama (free, no internet needed) developer-local
Edge deployments Cloudflare Workers AI optional per client

Work in code (conceptually):

// thin router picks provider
const model = router.pick('assistant', { clientPrefs });

// stream answer
const result = await generateText({ model, messages, tools });

What the AI can actually do

  • Answer with tools (search_records, get_monthly_stats, diff_documents, find_expiring_iso).
  • Retrieve knowledge via embeddings (pgvector) + keyword (tsvector) — the Instacart blog pattern.
  • Extract documents (invoice, PO, certificate) → structured fields.
  • Generate insights nightly: "TSR-20 contributed 31% of 2026 volume."

Tenant isolation in AI (critical)

Every AI call is scoped to the tenant: - tenant_id injected into every tool call. - Every tool queries SQL with the tenancy helper (Decision 1). - The Cerebras-style "plan + execute" loop is tenant-coded — can't leak cross-client.

What I will also build

  • Safety rails: assistant can't create/update records by default — only reads unless explicitly granted write tools.
